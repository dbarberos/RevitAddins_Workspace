# UI Design Guide: pyRevit Forms, WPF, and the MVVM Pattern

Developing tools for Revit requires interacting with the user to request data or selections. pyRevit offers two main paths: using its built-in rapid forms library (`pyrevit.forms`) or, for more complex tools, creating modern graphical interfaces using WPF and the MVVM pattern.

## 1. Rapid Forms (`pyrevit.forms`)
For simple scripts, pyRevit includes a large variety of pre-built windows that save you from having to design an interface from scratch.

### A. Alerts and Messages (`forms.alert`)
This is an excellent way to control flow (Flow Control) and interrupt processes if the user makes a mistake.
**Best practice:** Use alerts to warn the user and cancel execution using `script.exit()`.
```python
from pyrevit import forms, script

if not my_selection:
    # Show alert and stop the script
    forms.alert("No revision selected.", title="Script Canceled", warn_icon=False)
    script.exit()
```

### B. List Selection (`forms.SelectFromList`)
Allows the user to choose items from a list generated by your script. Supports multiple selection and has a built-in search bar.

**The `TemplateListItem` Trick (A simplified "ViewModel"):**
When you send Revit elements (e.g., *ViewTemplates*) directly to a list, pyRevit usually displays their code representation (`Autodesk.Revit.DB...`), which is not human-readable. The best practice is to create a custom class inherited from `forms.TemplateListItem` to show a friendly name in the UI (Front-end), but pass the element ID or the actual object behind the scenes (Back-end).

```python
from pyrevit import forms

# 1. Define the class to "translate" the object for the UI
class TemplateToPurge(forms.TemplateListItem):
    @property
    def name(self):
        # Show only the Template name to the user
        return self.item.Name 

# 2. Apply the class to our template list using List Comprehension
ui_options = [TemplateToPurge(vt) for vt in templates_unused]

# 3. Show the window to the user
selected = forms.SelectFromList.show(
    ui_options,
    title="Select Templates to Purge",
    button_name="Purge",
    multiselect=True
)
```

## 2. Advanced Interfaces with WPF (Windows Presentation Foundation)
If you need a fully custom window (with text fields, multiple dropdown menus, images, etc.), you must use the **WPF** framework. 

Developing with WPF in pyRevit strictly requires using **two separate files**:
1.  **XAML Script (Front-end):** A file similar to HTML but designed for desktop applications. It defines the visual layout (buttons, lists, containers).
2.  **IronPython Script (Back-end):** This is the logic that will provide the data from Revit, monitor events (like button clicks), and react to them.

**Best Practice (Using AI):**
Writing XAML code from scratch has a steep learning curve. It is highly recommended to use AI to generate the basic XAML structure by providing it with a functional "skeleton", and then fine-tune the design.

## 3. The MVVM Design Pattern
When using WPF, your tool's architecture should follow the **MVVM (Model-View-ViewModel)** design pattern. This pattern serves to completely separate the graphical design from the logical code, making your tool cleaner and easier to maintain.

*   **Model:** This is your main Python script. It is the part that knows how to use the Revit API to collect data (e.g., get all views in the project) and execute the business rules.
*   **View:** This is the XAML file. It displays the information visually for the user to interact with.
*   **View Model:** Acts as the **translator** in between. It takes the "raw" data you pulled from the Revit API in the *Model* and wraps it in compatible classes and formats so that the XAML file (*View*) can read and render them correctly (for example, taking a list of views and adapting them to fit in a visual `ListBox` block).

### Valid Revit API Context
It is a strict requirement that actions executed from a WPF interface interact with Revit within a Valid Revit API Context.
* **Golden Rule:** Any button in your WPF UI that modifies the BIM model must initiate and commit a Revit `Transaction`.

## 4. Evolution to Add-ins (C#)
If in the future your IronPython WPF tool grows so much that you need to protect the source code (compile it) and improve its execution speed, the recommended route is to migrate to C#.
For this, there is the **`revit-wpf-template`** (available on GitHub) or our project's dual-stack C# setup.
