# Steps to publish the Add-in on the Autodesk App Store

1. **Installer selection** – When you invoke the skill, the agent will ask if you want to use the **standard .bundle format** or a **custom installer**.
   - If you choose **bundle**, the agent will follow the `.bundle` package creation flow.
   - If you choose **custom**, you must provide the path to the installer (`.exe`/`.msi`) and the agent will copy it to `CustomInstaller/`.

2. **Creation of the `<AddInName>PublishPackage` folder** – The agent automatically creates a folder with the Add-in's name followed by `PublishPackage` (e.g. `MyAddinPublishPackage`).

3. **Basic structure** – Inside that folder, the following elements are generated:
   - `PrivacyPolicy.md` – privacy policy template.
   - `Screenshots/` – folder where to place **≥ 4 images** or **3 images + 1 video**.
   - `WebsiteInfo.txt` – contains `https://example.com` (replace with the actual URL).
   - `AppDescription.md` – placeholder text (minimum 4000 characters). If `User_Guide.md` generated by `revit-addin-doc-manager` exists, its content will be copied here.
   - `DigitalSignatureInfo.md` – notes on the digital signature of the installer (optional).
   - `Steps.md` – this file itself which describes the entire process.

4. **Bundle generation** – The agent extracts the project's metadata, generates `PackageContents.xml`, copies the `.dll` and the adapted `.addin`, and creates the `.bundle` structure inside the `Contents/` folder.

5. **Documentation** – If there is a `User_Guide.md` in the project root, the agent will convert it to `Help.html` inside `Contents/Resources/` and also insert it into `AppDescription.md`.

6. **Compression** – Upon completion, the agent suggests compressing the `<AddInName>.bundle` folder into a `.zip` ready to be uploaded to the Autodesk App Store.

7. **Final checklist** – Verify that:
   - The privacy policy is complete.
   - At least 4 screenshots (or 3 + video) have been added.
   - The description has at least 4000 characters.
   - The website URL is updated.
   - If a custom installer is used, it is digitally signed (optional).
   - The `PackageContents.xml` file contains the correct data.

Once these steps are completed, the package is ready for submission to Autodesk.
